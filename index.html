01 / WINDOWS

README, Markdown e GitHub Desktop

No Windows, você pode usar o GitHub Desktop para controlar versões visualmente e o Bloco de Notas ou VS Code para editar arquivos Markdown.

Etapa A — Prepare as ferramentas

  1. Instale o GitHub Desktop e entre com sua conta GitHub.
  2. Instale um editor como o Visual Studio Code (opcional, mas recomendado).
  3. Crie uma pasta para seus projetos, por exemplo Documentos\\Projetos.

Etapa B — Crie o repositório

  1. Abra o GitHub Desktop e escolha File → New repository.
  2. Defina um nome sem espaços, como meu-primeiro-projeto, escolha a pasta local e marque a opção para criar um README.
  3. Clique em Create repository. Para publicar, use Publish repository e revise se quer deixar o projeto público ou privado.

Etapa C — Edite o README

  1. Abra a pasta do projeto no VS Code.
  2. Abra README.md e escreva o objetivo do projeto, requisitos e como executar.
  3. Salve com Ctrl + S. Volte ao GitHub Desktop: as mudanças aparecerão em Changes.

Etapa D — Registre e envie as mudanças

  1. Revise a lista de arquivos alterados e o diff.
  2. Escreva uma mensagem objetiva, por exemplo docs: explica como executar o projeto.
  3. Clique em Commit to main e depois em Push origin para enviar as mudanças publicadas ao GitHub.
Commit registra um conjunto de alterações no histórico local. Push envia commits para o repositório remoto. São ações diferentes.
02 / LINUX

README, Markdown e Git pelo terminal

O GitHub Desktop oficial não oferece uma versão nativa oficial para Linux. Neste guia, use Git pelo terminal e, se quiser, VS Code ou outro editor disponível na sua distribuição.

Etapa A — Instale o Git

Em distribuições baseadas em Ubuntu ou Debian, abra o terminal e execute:

sudo apt update sudo apt install git

Em Fedora, o comando costuma ser sudo dnf install git. Em outras distribuições, use o gerenciador de pacotes correspondente.

Etapa B — Configure sua identificação

git config --global user.name "Seu Nome" git config --global user.email "seu-email@exemplo.com"

Use um e-mail adequado à sua conta. Essa configuração identifica os commits; ela não faz login no GitHub.

Etapa C — Crie o projeto e o README

mkdir -p ~/Projetos/meu-primeiro-projeto cd ~/Projetos/meu-primeiro-projeto git init printf "# Meu primeiro projeto\\n\\nO que ele faz e como executar.\\n" > README.md git status

Etapa D — Registre as mudanças

git add README.md git commit -m "docs: adiciona README inicial"

Para publicar no GitHub, crie um repositório vazio na página do GitHub e siga a URL e as instruções exibidas. O fluxo SSH ou HTTPS exige autenticação; senha comum da conta não é aceita para Git via HTTPS.

git branch -M main git remote add origin https://github.com/SEU-USUARIO/SEU-REPOSITORIO.git git push -u origin main
Substitua a URL de exemplo pela URL real do seu repositório. Se aparecer erro dizendo que o remoto já tem commits, não force o envio: leia a mensagem e sincronize o histórico com cuidado.

01 / PROPOSTA

O que é o SQ Labs?

É o ambiente de aprendizagem do projeto Informática p/ Internet Itinerante. A ideia é aproximar conhecimentos de programação, banco de dados e colaboração digital de estudantes que estão começando.

Em vez de apresentar apenas definições, o material combina explicação, exemplo, prática guiada e reflexão sobre erros comuns.

02 / COMO APRENDER

Conteúdo → prática → revisão

Primeiro, leia a explicação e observe o exemplo. Depois, faça uma atividade. Use o retorno para revisar o conceito e registre dúvidas no seu painel.

O erro faz parte do processo: o importante é entender por que uma solução funciona ou não.

04 / TRANSPARÊNCIA

Como os dados funcionam

Preferências, metas, anotações, atividades criadas e progresso são guardados no armazenamento local do navegador deste dispositivo. O site não cria conta nem envia esses dados a um servidor.
